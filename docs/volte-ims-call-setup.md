# برقراری تماس VoLTE از طریق IMS

بررسی گام‌به‌گام فرآیند ثبت‌نام IMS (IMS Registration) و برقراری تماس صوتی (VoLTE Call Setup) میان دو کاربر، با افزودن یک شبکه IMS مبتنی بر Kamailio به هسته 4G راه‌اندازی‌شده در فاز اول.

> **درباره مقادیر این سند:** این فرآیند به‌صورت عملی روی زیرساخت IMS راه‌اندازی‌شده پیاده و در Wireshark بررسی شد. شناسه‌ها و مقادیر نمونه (شماره SIP، پورت‌های RTP و...) در این سند برای نمایش ساختار صحیح پیام‌ها آورده شده‌اند و مستقیماً از یک Capture خاص استخراج نشده‌اند.

## معماری

```
UE-A ─┐                                   ┌─ UE-B
      │        ┌── Kamailio (IMS) ──┐     │
      └──eNB──►│ P-CSCF / S-CSCF /  │◄──eNB┘
               │ I-CSCF, HSS(IMS)   │
               └────────┬───────────┘
                         │
                  EPC (open5GS) — همان هسته 4G فاز ۱
```

| عنصر | نقش |
|---|---|
| P-CSCF | اولین نقطه تماس UE با شبکه IMS، مسیر تمام سیگنالینگ SIP |
| I-CSCF | مسیریابی اولیه درخواست‌ها به S-CSCF مناسب |
| S-CSCF | مدیریت اصلی نشست SIP، احراز هویت IMS، اعمال سرویس‌ها |
| HSS (IMS) | نگهداری پروفایل IMS کاربر (IMPI/IMPU) |

---

## ۱. پیش‌نیاز: Dedicated Bearer برای سیگنالینگ IMS

- پیش از هر ارتباط SIP، UE باید یک **Dedicated EPS Bearer** با QCI=5 (اختصاصی سیگنالینگ IMS، با اولویت بالا و بدون تضمین نرخ گارانتی‌شده) از طریق EPC دریافت کند.
- این Bearer، مسیر اختصاصی برای تبادل پیام‌های SIP بین UE و P-CSCF فراهم می‌کند (جدا از Bearer پیش‌فرض داده عمومی که در فاز ۱ ایجاد شد).

## ۲. ثبت‌نام IMS (IMS Registration)

- UE یک پیام `SIP REGISTER` به سمت P-CSCF ارسال می‌کند؛ این پیام شامل هویت عمومی کاربر (**IMPU**، مثلاً `sip:user-A@ims.mnc001.mcc001.3gppnetwork.org`) و هویت خصوصی (**IMPI**) است.
- P-CSCF این درخواست را به I-CSCF و از آنجا به S-CSCF مناسب هدایت می‌کند.
- S-CSCF از HSS(IMS) بردار احراز هویت را استعلام می‌کند (مشابه منطق AKA در لایه‌های پایین‌تر شبکه) و یک چالش `401 Unauthorized` (شامل RAND/AUTN داخل هدر `WWW-Authenticate`) به UE بازمی‌گرداند.
- UE با محاسبه پاسخ صحیح، `REGISTER` را با هدر `Authorization` مجدداً ارسال می‌کند؛ S-CSCF با تایید پاسخ، ثبت‌نام را با `200 OK` تکمیل می‌کند.

## ۳. برقراری تماس (Call Setup)

فرض: UE-A می‌خواهد با UE-B تماس بگیرد؛ هر دو پیش‌تر IMS Registration را کامل کرده‌اند.

1. **INVITE:** UE-A یک پیام `SIP INVITE` برای UE-B ارسال می‌کند (از طریق P-CSCF → S-CSCF → ... → P-CSCF کاربر مقصد). این پیام حاوی یک بلوک **SDP** (Session Description Protocol) است که کدک صوتی پیشنهادی (مثلاً AMR-WB) و پورت RTP محلی UE-A را مشخص می‌کند.
2. **Provisional Responses:** شبکه و UE-B به‌ترتیب پاسخ‌های موقت `100 Trying` و `180 Ringing` بازمی‌گردانند (اعلام در حال زنگ خوردن گوشی مقصد).
3. **Resource Reservation:** پیش از برقراری نهایی تماس، یک **Dedicated Bearer صوتی** با QCI=1 (نرخ‌بیت تضمین‌شده، مناسب ترافیک real-time صوت) برای هر دو UE ایجاد می‌شود تا کیفیت مکالمه تضمین شود.
4. **200 OK:** UE-B تماس را می‌پذیرد؛ در پاسخ `200 OK`، SDP نهایی (کدک انتخاب‌شده و پورت RTP نهایی UE-B) ارسال می‌شود.
5. **ACK:** UE-A با ارسال `ACK`، برقراری نشست را تایید می‌کند؛ از این لحظه مکالمه فعال است.

## ۴. تبادل رسانه (Media Path)

- پس از تکمیل SDP Negotiation، جریان صدا به‌صورت مستقیم روی پروتکل **RTP** (روی Bearer صوتی اختصاصی QCI=1) بین دو UE (از طریق User Plane شبکه، نه سرورهای IMS) جابه‌جا می‌شود.
- سیگنالینگ SIP (روی Bearer QCI=5) در طول تماس صرفاً برای کنترل نشست فعال باقی می‌ماند (مثلاً برای Hold، Transfer یا پایان تماس).

## ۵. پایان تماس (Call Teardown)

- هر یک از طرفین با ارسال `SIP BYE` درخواست پایان تماس می‌دهد؛ طرف مقابل با `200 OK` تایید می‌کند.
- شبکه در ادامه، Bearer اختصاصی صوتی (QCI=1) که دیگر مورد نیاز نیست را آزاد می‌کند؛ Bearer سیگنالینگ IMS (QCI=5) برای تماس‌های بعدی فعال باقی می‌ماند.

---

## خلاصه فرآیندهای تحلیل‌شده

| فرآیند | پیام‌های کلیدی |
|---|---|
| IMS Registration | SIP REGISTER, 401 Unauthorized (AKA Challenge), 200 OK |
| Call Setup | INVITE, 180 Ringing, 200 OK, ACK, SDP Negotiation |
| Bearer Management | Dedicated Bearer QCI=5 (سیگنالینگ) و QCI=1 (صدا) |
| Media | RTP روی Bearer صوتی اختصاصی |
| Teardown | BYE / 200 OK |
