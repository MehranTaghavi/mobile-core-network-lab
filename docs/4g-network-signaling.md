# راه‌اندازی و تحلیل سیگنالینگ شبکه 4G (RAN تا Core)

بررسی گام‌به‌گام فرآیندهای Attach، احراز هویت (EPS-AKA) و برقراری Bearer داده در یک شبکه 4G/LTE واقعی، راه‌اندازی‌شده با srsRAN (eNB) و open5GS (EPC).

> **درباره مقادیر این سند:** این پروژه به‌صورت عملی، با یک UE و SDR واقعی (USRP B210) راه‌اندازی و روی آن **در Wireshark سیگنالینگ Capture و تحلیل شد**. مقادیر پارامترهای رمزنگاری (RAND/AUTN/RES) و برخی شناسه‌های عددی که در این سند آمده‌اند، به‌دلیل در دسترس نبودن فایل pcap اصلی، **نمونه‌های نمایشی** بر اساس ساختار استاندارد 3GPP هستند تا جریان واقعی پیام‌ها را به‌درستی نشان دهند — نه استخراج مستقیم از آن Capture.

## معماری

```
UE ──(radio, USRP B210)──► eNB (srsRAN) ──(S1AP/GTP)──► EPC (open5GS)
                                              │
                                MME ─ HSS ─ SGW ─ PGW
```

| عنصر | نقش |
|---|---|
| eNB | ایستگاه پایه، ارتباط رادیویی با UE و رله سیگنالینگ S1AP به MME |
| MME | مدیریت Mobility، Attach، Authentication و Bearer Signaling |
| HSS | نگهداری پروفایل مشترک (IMSI, Key, OPC) و تولید بردار احراز هویت |
| SGW / PGW | مسیر داده کاربر (User Plane) و تخصیص IP، اتصال به اینترنت |

---

## ۱. جست‌وجوی سلول و برقراری اتصال رادیویی (RRC)

- UE با اسکن باندهای فرکانسی، سیگنال eNB را پیدا و همگام‌سازی زمانی/فرکانسی (Cell Search) انجام می‌دهد.
- از طریق فرآیند Random Access (پیام‌های Msg1–Msg4، شامل Preamble و RRC Connection Setup) یک اتصال RRC بین UE و eNB برقرار می‌شود.
- این بخش، مشابه فاز ۵G، لایه رادیویی صرف است و در Capture سطح شبکه (بین eNB و EPC) دیده نمی‌شود.

## ۲. Attach Request (NAS)

- UE از طریق eNB (با پروتکل S1AP، حامل پیام NAS) یک `Attach Request` برای MME ارسال می‌کند.
- این پیام شامل هویت UE (IMSI در اولین اتصال، یا GUTI در اتصالات بعدی)، قابلیت‌های UE و نوع درخواست PDN (پیش‌فرض: اتصال اینترنت) است.

## ۳. احراز هویت EPS-AKA

- MME برای احراز هویت کاربر، از **HSS** بردار احراز هویت (Authentication Vector) درخواست می‌کند. HSS با استفاده از کلید مشترک (Key) و OPC کاربر که از پیش در آن ثبت شده، این بردار را تولید می‌کند:

  ```
  RAND:   (مقدار نمونه) a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4
  AUTN:   (مقدار نمونه) 1122334455667788990011223344
  XRES:   (مقدار نمونه) 99aabbccddeeff0011223344
  KASME:  (مشتق‌شده در MME پس از احراز هویت موفق)
  ```

- MME مقادیر `RAND` و `AUTN` را در پیام `Authentication Request` برای UE ارسال می‌کند.
- UE با استفاده از کلید ذخیره‌شده در SIM/USIM خود، مقدار `AUTN` را اعتبارسنجی (تایید تعلق به شبکه صحیح) و پاسخ `RES` را محاسبه و در `Authentication Response` بازمی‌گرداند.
- MME مقدار `RES` دریافتی را با `XRES` مقایسه می‌کند؛ تطابق این دو، هویت کاربر را تایید می‌کند.

## ۴. NAS Security Mode Command

- پس از احراز هویت موفق، MME الگوریتم‌های رمزنگاری و یکپارچگی (Integrity) مورد توافق را از طریق `Security Mode Command` به UE اعلام می‌کند.
- UE با `Security Mode Complete` تایید می‌کند؛ از این نقطه، تمام پیام‌های NAS بین UE و MME رمزنگاری و یکپارچگی‌سنجی می‌شوند.

## ۵. Attach Accept و برقراری Default Bearer

- MME با هماهنگی SGW و PGW، یک **Default EPS Bearer** (مسیر داده پیش‌فرض کاربر، معمولاً با QCI=9 برای ترافیک عمومی اینترنت) ایجاد می‌کند.
- PGW یک آدرس IP به UE تخصیص می‌دهد.
- پیام `Attach Accept` (شامل آدرس IP تخصیصی، هویت جدید GUTI، و پارامترهای Bearer) از طریق eNB برای UE ارسال و با `Attach Complete` تایید می‌شود.
- ارتباط بین SGW و PGW با پروتکل **GTP-C** (کنترل) برای Signaling و **GTP-U** (داده) برای عبور واقعی ترافیک کاربر برقرار می‌شود.

## ۶. اعتبارسنجی اتصال اینترنت

- پس از تکمیل Attach، UE از طریق مسیر End-to-End (UE → eNB → SGW → PGW → اینترنت) قادر به ارسال و دریافت ترافیک داده است.
- اعتبارسنجی نهایی این فاز، با یک درخواست ساده (مثل Ping یا باز کردن یک صفحه وب) روی UE و مشاهده‌ی ترافیک متناظر در Wireshark انجام شد.

---

## خلاصه فرآیندهای تحلیل‌شده

| فرآیند | پیام‌های کلیدی |
|---|---|
| Authentication | Authentication Request/Response (RAND, AUTN, RES) |
| Session Establishment | Attach Request/Accept, Default Bearer Setup (GTP-C) |
| اتصال به اینترنت | ترافیک GTP-U بین UE و PGW، تایید عملکرد End-to-End |
